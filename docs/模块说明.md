# 功能模块说明

模块按功能分目录。用户认证、权限判断、项目管理与文件操作各有自己的实现；HTTP和启动入口只组织调用。每个目录的 `__init__.py` 声明公开接口，内部文件使用相对导入。

| 模块 | 公开入口 | 自己负责的内容 |
| --- | --- | --- |
| application | AppConfig、create_app、run | config.py集中配置；factory.py装配服务、管理lifespan和关闭顺序 |
| database | Database、verify_database_integrity | schema.py定义当前结构；connection.py管理连接/事务；integrity.py检查结构和完整性 |
| users | Users、UserStore、MAX_USERS | service.py实现认证、账号管理及密码；store.py持有最多200人的RAM缓存，负责加载、事务及同步数据库；Users显式接收Permissions并共用其UserStore |
| permissions | Permissions、permission_catalog | catalog.py定义14项型号权限；service.py读取当前身份、计算可见型号、配置授权、执行实时检查 |
| projects | ProjectService | service.py提供型号/版本管理；creation.py处理创建补偿；renames.py处理改名/恢复；paths.py管理本功能的目录检查 |
| files | FileService、FILE_CATEGORIES、FILE_TABLES | service.py持有文件门禁、上传/下载资源及上传流程；catalog.py文件与版本曲线名称查询；reviews.py审核；authorizations.py下载授权；synchronization.py扫描同步；publication.py联合文件/SQL发布恢复；transfers.py句柄；rules.py分类/版本/上传校验 |
| remote | RemoteService、RemoteControlConfig、RemoteError | 设备连接、分页、租约、幂等记录、frp/CFB、RFB双向转发及清理 |
| http | install_routes | 路由、认证头解码、请求校验、摘要响应、流式适配、文档和ASGI并发门禁 |
| runtime | start_service、stop_service、service_status、run_managed | 识别并管理本项目Windows进程，校验PID身份和运行根，记录启动/停止状态 |
| storage | safe_path、durable_copy、FileLock、RuntimeLock等 | paths.py校验受管路径；io.py摘要与持久写入；locking.py持有操作系统文件锁 |
| contracts | HubError、decode_json、digest_data等 | 统一错误对象、严格JSON、RFC8785及五字段响应数据；tasks.py定义任务完成与取消传播合同 |

## 调用与状态归属

```mermaid
flowchart TD
    App[application：装配] --> Permissions[permissions]
    App --> Users[users]
    App --> UserStore[users.UserStore：唯一用户缓存]
    App --> Projects[projects]
    App --> Files[files]
    App --> Remote[remote]
    App --> DB[database]
    HTTP[http：请求适配] -. app.state中的显式实例 .-> Permissions
    HTTP -.-> Users
    HTTP -.-> Projects
    HTTP -.-> Files
    HTTP -.-> Remote
    Users --> Permissions
    Users --> UserStore
    Permissions --> UserStore
    UserStore --> DB
    Projects --> Permissions
    Projects --> Files
    Files --> Permissions
    Users --> DB
    Projects --> DB
    Files --> DB
    Runtime[runtime：进程编排] --> App
    DB --> Storage[storage：文件锁和磁盘原语]
    Files --> Storage
    Projects --> Storage
```

图中HTTP虚线表示运行时调用，不要求业务模块反向导入HTTP。基础错误、JSON和任务完成契约供各模块按需使用。application、http、remote共同使用contracts.finish_task；同步适配统一为contracts.run_blocking。`tests/test_architecture.py`检查实际模块导入无环、跨模块使用公开接口，以及Users/FileService不再承担项目或权限转发。

应用创建一个Database、UserStore和Permissions，再显式注入Users、FileService、ProjectService。数据库打开后加载用户缓存，再校验权限、恢复项目和文件，最后开放服务；离线维护使用同样的装配。UserStore与Database共享RLock，用户读操作返回副本，修改先更新RAM再同步持久化，失败恢复或停用缓存，关闭清空缓存。所有用户表读写只由UserStore完成，新库初始账号由数据库初始化创建。

型号可见性与资源操作权限共用Permissions，检查当前RAM用户记录；管理员隐式覆盖全部型号，普通用户仅访问获授权型号。同型号的所有版本共用授权，资源按版本目录独立。用户缓存不代替型号或文件数据库。FileService子处理器只引用所属服务，不另外创建数据库连接、锁或句柄集合；审核提交人、固件上传人及下载授权创建人均从同一缓存读取。

项目目录改名通过FileService公开的协调接口检查正在上传的文件，并设置、解除自己的恢复门禁。文件发布恢复只解除文件自身门禁。所有组合变更共享数据库RLock和事务，权限检查与提交不脱离同一受控流程。

两项跨模块数据协调保留在同一个原子流程内：文件扫描使用Database事务，根据磁盘目录登记型号/版本；项目改名使用UserStore外层事务，同步文件、审核、下载授权路径，并通过UserStore更新用户的型号权限。后者保证目录或SQL失败时用户RAM与数据库一起恢复。它们不各自缓存另一模块状态，也不引入仅用于转发的仓储层。常规项目管理通过ProjectService，账号管理通过Users，权限管理通过Permissions。

## 文件模块使用方式

```python
files.catalog.list_files(project_id=version_id, category="curve", actor=actor)
files.catalog.list_curve_names(version_id, actor=actor)
files.reviews.approve_review(actor, review_id)
files.authorizations.get_download_authorization(code)
files.synchronizer.synchronize(metadata)
```

同步文件操作可能阻塞；HTTP通过contracts.run_blocking在线程执行，认证、项目查询也直接使用此接口，不依赖文件传输模块。上传使用 `begin_upload` / `begin_curve_update` 返回句柄，调用方必须关闭；下载处理器把句柄登记到所属FileService，由响应收尾或服务关闭释放。三个下载入口共享相同资源归属，已有回归测试。

曲线模板由FileCatalog按版本所属型号读取 `型号/模板.json`，在文件操作锁内检查当前型号权限。同型号各版本共用，扫描时不把该文件登记为版本或曲线；普通文件仍按版本目录隔离。

曲线名称与文件名在当前版本中分别唯一。FileService复用待审/活动上传扫描检查占用，审核模块复查已发布名称，数据库以版本和名称、版本和文件名的唯一约束防止正式记录重复；修改原曲线时排除其自身记录。

## 本轮职责与依赖复核

- 数据库通过storage.FileLock取得维护锁；文件锁原语仅由storage实现。数据库层负责将锁打开失败映射为数据库错误，锁争用保留原错误码。
- 权限模块直接复用contracts.decode_json，权限值/型号规则仍由permissions负责。
- 远控只接收RemoteControlConfig，应用聚合配置由application负责拆分。
- 取消等待统一处理；HTTP独立保留创建句柄期间取消后的回收，不将资源归属加入公共任务工具。
- 新库检查报告只包含from_revision/to_revision，移除从未生成备份或迁移清单的空字段；项目改名移除新待审记录从不产生的original.path兼容分支。
- 文件发布与审核清理使用同一Publisher恢复流程；已提交的操作保留成功结果，清理失败设置恢复门禁，继续恢复后再开放文件业务。

## 代码清理复核（2026-11-14）

- UserStore.write统一账号与授权操作的数据库错误转换，Users和Permissions不再各自包一层同样的写入适配。UserStore.transaction仍供型号改名等跨模块事务使用，保留各业务的错误语义。
- 数据库初始化结果只由MigrationReport表达，移除没有业务消费方的created状态；远控移除从未生效的debug_logging配置，日志继续由宿主管理。
- 应用run复用create_app已解析的配置，避免重复规范化路径；HTTP的GET和签名POST文件JSON读取共用响应适配，删除三个没有错误生产方的旧状态映射。
- 审核列表一次查询待审完整记录，避免按ID逐条重查；搜索只建立一次ASCII转换表并折叠一次查询词，无搜索词时不构造搜索字段。权限过滤、分页、非ASCII精确和字面匹配规则保持不变。
- 提交前权限与摘要复查、路径身份、事务恢复、远控代际及进程身份检查均保留；它们分别保护不同调用阶段，不能按外观相似视为重复代码。

## 入口与工程辅助目录

`main.py`是CLI及默认ASGI入口，`service.py`导出默认ASGI对象。`scripts/`是检查、初始化、同步与进程管理命令；`deployment/windows/`是PowerShell启动/停止脚本；`tests/`验证业务、协议、并发、恢复和模块结构；`docs/`保留模块说明、验证报告和DeviceBridge功能基线清单。

`data/`属于实际运行数据，`dist/`是构建产物。二者不作为业务模块。当前重构不修改运行数据、不管理用户已启动的服务，也不恢复历史版本兼容。
